# Palantir Ontology 详情扩充设计

## 目标

在现有 Palantir Ontology 独立根模块上补充可学习、可落地的节点详情。保持知识树结构和公开页面入口不变，不增加节点数量；点击 14 个 Ontology 子节点时，详情面板应同时展示定义、核心要素、典型例子和落地提示。

## 当前问题

Ontology 节点目前只有 `summary`，`addNode` 将摘要同时作为 `body`。详情面板只能把一段简短文字显示为普通段落，缺少概念边界、实施上下文和风险提示。

## 范围

### 包含

- 为 14 个 Ontology 子节点增加结构化详情。
- 为详情补充更完整的搜索标签。
- 详情面板支持带标题的详情区块。
- 保持 `index.html` 与 `rag-concepts-preview.html` 内容同步。
- 保持现有 RAG 节点的兼容渲染。

### 不包含

- 不增加 Ontology 子节点数量。
- 不修改根节点数量、已有 RAG 节点或页面入口。
- 不引入后端、数据库、构建工具或外部运行时依赖。
- 不把未经核实的 Palantir 产品功能写成确定性 API 承诺。

## 内容模型

在 Ontology 数据区增加按节点 ID 索引的详情数据，推荐字段：

```js
const ontologyDetails={
  'ontology-object-types':{
    tags:['Object Types','对象建模','实体','生命周期'],
    sections:[
      {label:'定义',text:'描述对象类型负责表达的业务实体，以及它与底层数据源和运营流程的边界。'},
      {label:'核心要素',text:'稳定标识、业务属性、关系、生命周期、访问策略和数据来源。'},
      {label:'典型例子',text:'将设备建模为对象类型，连接位置、维护记录、告警和负责人。'},
      {label:'落地提示',text:'先确定稳定的业务标识，再设计属性和关系；不要把临时分析字段直接固化为核心对象模型。'}
    ]
  }
};
```

节点创建完成后，将详情数据合并到对应节点。`summary` 继续用于树节点、搜索摘要和图谱标签；`sections` 只用于详情面板。旧节点没有 `sections` 时，详情面板继续使用现有 `body`/`summary` 回退逻辑。

每个 Ontology 子节点必须包含四个区块：

1. **定义**：说明概念及其边界。
2. **核心要素**：说明模型、数据、权限或执行机制中的关键组成。
3. **典型例子**：使用资产、订单、设备、人员或业务流程等可理解案例。
4. **落地提示**：说明实施建议、常见误区、性能约束或治理风险。

## 14 个节点的内容重点

| 节点 | 必须覆盖的重点 |
|---|---|
| Ontology 概念与边界 | 对象、属性、关系、动作；语义层与数据库表的边界 |
| Object Types 对象类型 | 稳定标识、属性、关系、生命周期、权限 |
| Properties 属性 | 标量、时间序列、地理和派生属性；来源映射与新鲜度 |
| Link Types 关系类型 | 业务语义、方向、基数、遍历和依赖 |
| Interfaces 接口 | 共享能力形状、复用、兼容性和多对象类型协作 |
| Actions 动作 | 参数、校验、副作用、审计、幂等和授权 |
| Functions 函数 | 派生计算、异步执行、外部调用、失败处理 |
| 对象集合与查询 | 过滤、关系遍历、权限边界、稳定查询和性能 |
| 数据接入与对象映射 | 数据集、虚拟表、外部系统、主键映射、血缘和质量 |
| 语义层与数字孪生 | 现实实体、状态、事件、统一标识和数据新鲜度 |
| 安全与治理 | 对象/属性/动作权限、标记、审计、最小权限和变更治理 |
| 运营工作流 | 状态、触发器、动作、函数、通知、审批和可观测性 |
| 本体驱动应用 | 对象视图、动作表单、仪表盘、写回和业务用户体验 |
| AI 与智能体集成 | 语义 grounding、工具动作、权限、确认、审计和评估 |

## 详情面板设计

- 对具有 `sections` 的节点，按四个区块依次渲染小标题和正文。
- 所有标题和正文都必须经过现有 `esc` 函数转义，不能把详情文本作为 HTML 直接注入。
- 对没有结构化详情的旧节点，保留现有正文显示方式。
- 详情面板继续显示节点类型、面包屑、父节点、子节点和相关节点。
- 不改变搜索、筛选、邻居展开、主题切换和重置视图行为。

## 搜索与关系

- 新标签参与现有 `matches()` 搜索逻辑。
- 详情正文不直接参与搜索，避免搜索结果因长文本产生噪声；关键术语必须放入 `tags` 或 `summary`。
- 本次不新增跨节点关系；已有根节点关系和 RAG 关系保持不变。

## 验证标准

1. 两份 HTML 均包含 14 个节点的四段详情数据。
2. 两份 HTML 字节内容一致。
3. 页面初始显示 `74 个概念节点` 和 `74 节点`。
4. 点击任一 Ontology 节点，详情面板出现四个区块标题。
5. 搜索 `Object Types`、`对象建模`、`AI 与智能体` 能命中对应节点。
6. 旧 RAG 节点仍能正常显示详情，搜索和筛选无回归。
7. 本地浏览器和公开 GitHub Pages 页面均可正常加载，无 JavaScript 错误。
